# Кэширование (написано агентом; в ТЗ файла нет — MISSING_FILES #29)

| Уровень | Где | Что кэшируется | Состояние |
|---|---|---|---|
| Ответы LLM | LiteLLM Proxy, `litellm_settings.cache` в `deploy/litellm/config.yaml` (Redis, TTL 24 ч) | одинаковые запросы (модель + сообщения + параметры); повтор после сбоя, повторное планирование того же запроса | включено в конфиге |
| Эмбеддинги | тот же кэш LiteLLM (`aembedding`) | одинаковые тексты | включено в конфиге |
| База знаний | `kernel/knowledge` | повторная индексация пересчитывает только изменённые файлы (`file_hash`) | реализовано (фаза 4) |
| Prompt caching провайдера (Anthropic `cache_control`) | — | длинный общий system prompt | **не реализовано**: `LiteLLMClient` не ставит `cache_control`. Кандидат на экономию |
| Состояние run | чекпойнты LangGraph (Postgres) | resume после HITL или рестарта не повторяет выполненные узлы | реализовано |

Кэш ответов опасен для недетерминированных задач: при `temperature > 0` повтор вернёт тот же ответ.
Для fixer это нормально (тот же вход → тот же патч), а новая попытка получает другой вход (новые ошибки гейтов).
Отключить кэш для одного запроса: заголовок `Cache-Control: no-cache` или `cache: {"no-cache": true}` в запросе к прокси.
